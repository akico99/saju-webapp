# 연애 리포트 무료·유료 결과 웹툰형 개편 계획

상태: 기획 제안. 사용자가 구현 전에 내용 및 모델 배분 설명을 요청했으므로 제품 코드 수정/하위 모델 실행은 시작하지 않는다.

## 목표와 범위
- 인연의 시기 무료 결과 및 유료 실제 결과를 모바일 세로 웹툰형으로 읽게 만든다.
- 현재 무료 결과는 LLM 없이 계산 데이터로 생성된다. 이 장점을 유지한다.
- 유료 결과는 sectionDefs/parseLoveText에서 구조를 가진 뒤 result_text로 저장되고 브라우저에서 제목으로 다시 분리된다. 이 연결을 깨지 않고 표시 전용 모델을 도입한다.
- 이번 범위는 연애 리포트. 평생사주/궁합 등 다른 결과 화면은 공통 컴포넌트 검증 이후 별도 적용한다.
- 운영 배포/가격/결제/서비스의 Claude 모델 변경 없음. 기존 LOVE_TIMING_ENABLED 게이트 유지.

## 무료 결과: 6개 장면
1. 개인화 표지: 이름, 선택한 상황, 여울의 인사. 무료 첫 장 표시.
2. 매력 한 가지: 기존 charm headline/base에서 확인되는 내용. 캐릭터 말풍선과 해설 카드.
3. 매력의 근거: 실제 found 항목만 표시. 없으면 존재하는 base만 사용. 숨긴 전문용어는 펼쳐보기.
4. 오행: 계산된 5개 값의 시각화, 색뿐 아니라 이름/숫자 병기.
5. 계절 흐름: 기존 seasons 범위만 보여주는 탭/타임라인. 성공확률로 표현하지 않음.
6. 무료 요약과 유료 안내: 무료에서 확인한 것과 전체에서 추가되는 내용을 구분. 유료 분석 데이터는 무료 응답/DOM에 넣지 않음.
- 명식은 기본 흐름 뒤에 접을 수 있는 근거 자료로 제공. 핵심 해설보다 먼저 어려운 표를 보게 하지 않는다.

## 유료 결과: 7장
1. 가장 강한 세 달
2. 서로 끌리는 사람의 특징 (drawn/draws를 같은 장 안에서 구분)
3. 만남이 생기기 쉬운 자리
4. 반복되는 관계 패턴
5. 조심할 관계의 신호
6. 현재 상황별 실천
7. 앞으로 12개월
- 각 장은 표제/장면 그림 → 짧은 해설 → 근거/상세 → 행동 순서. 없는 행동 문장을 임의로 만들지 않는다.
- 원문 전체 열람 기능 제공. 짧게 보이게 하려다 본문을 버리지 않는다.
- 전문용어 풀이, 월 카드 선택, 장 목차 이동, 로컬 읽던 위치 복원, 실천 체크 항목을 제공한다.
- 체크/읽기 위치는 리포트별로 구분하고 민감한 본문/생년월일을 새로 로컬 저장하지 않는다.

## 가독성과 연출
- 본문 16~18px, 줄간격 1.75~1.9, 한 말풍선 1~3문장 목표. 자동 글자 자르기 금지.
- 원화 장면은 18~24개 패널 사이에 선택적으로 배치. 모든 문단마다 같은 얼굴 반복 금지.
- 원화는 여울의 인사/설명/공감/생각/주의/응원 6종과 만남/거리감/대화/새 출발 상황 그림 4종을 초기 자산 묶음으로 제안.
- 같은 인물 정체성을 유지하는 편집 방식으로 제작. 현재 신규 원화를 기준으로 하되 다른 세션의 사용자 원본이 제공되면 교체.
- 그림은 사주에서 특정 외모/사건을 예언한 실제 묘사로 제시하지 않는다.
- 등장 모션 200~350ms, 차트 전환, 탭 선택 피드백. 강제 타자 효과/자동 스크롤/반복 탭으로 원문 잠금 없음.
- reduced-motion 설정 시 모션 생략. JS/이미지 실패 시에도 본문 읽기 유지.
- 이미지는 사전 생성/압축/지연 로딩. 고객마다 실시간 이미지 API 호출 없음.

## 구현 파일 소유권과 모델 배분
총괄(현재 모델): 데이터 계약, 스토리보드, 이미지 생성, 파일 경계 결정, 통합, 최종 검수.
OpenAI GPT-6 Luna: public/love-reading-model.js 신규 표시 데이터 어댑터 및 관련 데이터 테스트. 생성문을 실행 가능한 HTML로 취급하지 않고 텍스트로 변환. 기존/누락/긴 본문 fallback. 원문 보존.
Anthropic Claude Sonnet 5.5: public/love-reading-view.js, public/love-assets/reading.css 담당. 무료/유료 공통 패널, 말풍선, 장면, 목차, 월 탭, 접근성/모션. 데이터 계약 고정 후 병렬 작업.
Anthropic Claude Haiku 5.5: docs 내 자산 목록/상황별 문구 목록/누락 체크리스트 작성. 사주 계산/결제/최종 품질 판정 소유권 없음.
통합 시 총괄이 public/love.html과 public/love-app.js 연결을 단독 수정한다.
별도 GPT-6 Luna 검토: 구현 에이전트와 분리된 실행으로 테스트/데이터 노출/기존 주문 호환 검토.
- 부모 포함 동시 4개 슬롯. 먼저 두 구현자와 경량 문서 작업자를 배치하고 종료 이후 검토자를 실행.
- 모두 공유 코드베이스이며 다른 작업자의 수정을 되돌리지 않도록 명시한다.
- 여기 모델명은 현재 위임 도구에서 사용 가능한 실행 모델을 뜻한다. 서비스 고객 풀이용 API 모델 선택과 별개.

## 실행 순서
- [ ] 1. 화면/표시 데이터 계약과 무료 6장면·유료 7장 스토리보드 확정.
- [ ] 2. 무료 계산 결과 및 유료 고정 예시 fixture 마련. 예시임을 표시하고 실제 결과와 구분.
- [ ] 3. 모델별 작업 분배 및 이미지 자산 제작. 공유 파일 수정 금지.
- [ ] 4. 무료 결과부터 연결/검수, 동일 컴포넌트로 유료 결과 연결.
- [ ] 5. 읽던 위치/체크/목차/모션 연결. 누락 항목과 구형 원문 fallback 검수.
- [ ] 6. 실제 생성 결과 검수. 기존 기록의 API 크레딧 부족이 해결됐는지 이 단계에서 확인. 실패하면 실제 생성 검증 미완료로 명시.
- [ ] 7. 독립 검토 및 비공개 미리보기 제공. 운영 배포는 별도.

## 검증 기준
- 320/390/768/1280px에서 가로 넘침/텍스트 잘림 없음.
- 솔로/썸/연애/이별, 시각 모름, 매력 항목 없음, 긴 이름, 빈 본문, 긴 문단, 이미지 실패.
- 무료 계산값/월 순서/본문 내용 보존. 무료에 유료 본문 누출 없음.
- 기존 저장 주문 읽기, 로그인 복원, 생성 대기/실패/재열기 회귀 확인.
- 동작 감소/키보드 탐색 가능. 원문 읽기를 모션이나 클릭으로 강제 지연하지 않음.
- 고객별 추가 이미지 생성 비용 없음. 정확한 추가 LLM 원가는 실제 사용 토큰 확인 전 숫자로 약속하지 않음.
