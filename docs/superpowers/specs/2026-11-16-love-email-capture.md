# 연애 무료 분석: 결과 전 이메일 받기 + 후속 메일

사용자 승인(2026-11-16 "진행해"). 경쟁사(용용·타이트)처럼 결과를 보여 주기 직전에 이메일을 받는다. 목적: 무료 결과를 본 사람에게 두 번째 기회를 만든다(지금은 126명 중 연락처 0, 구매 0).

## 결정 사항

| 항목 | 결정 |
|---|---|
| 위치 | 입력 마지막 단계: 이름 다음, '입력 확인' 바로 앞 새 단계 |
| 필수 여부 | 이메일·필수 동의는 필수. 건너뛰기 없음 |
| 받는 대신 주는 것 | "결과를 메일로도 보내 드려요" + (선택 동의 시) "1위 달이 시작되면 알려 드려요" |
| 결과 표시 | 이메일 입력 뒤 화면에 바로 보여 준다(지금과 같음). 결과 요약 메일 1통을 함께 보낸다 |
| 후속 메일 | 판매 메일 수신 동의자에게만: 1일 뒤, 3일 뒤, 1위 달 시작일(그 달 1일) 각 1통 |
| 가격 | 바꾸지 않는다(연애 14,900원) |
| 방침 | 개인정보처리방침을 기능과 같은 날 개정·시행하고 개정 안내를 함께 단다(사용자 판단: 7일 대기 없음) |
| Meta 이벤트 | Lead는 지금처럼 결과 화면 표시 때. 새 맞춤 이벤트 EmailSubmit(이메일 단계 통과) 추가 |

## 동의 문구(화면)

- [필수] 개인정보 수집·이용: 이메일·이름(별명)·생년월일시·성별·연애 상황을 무료 분석 결과 전달과 메일 링크로 결과 다시 보기에 씁니다. 30일 뒤 삭제합니다. 동의하지 않으면 무료 분석을 볼 수 없어요.
- [선택] 광고성 정보 수신: 1위 달 시작 알림과 전체 풀이 안내를 이메일로 받아요. 언제든 메일 아래 링크로 그만 받을 수 있어요. 동의하면 위 정보를 수신 거부 또는 마지막 알림 뒤 30일까지(최대 13개월) 보관합니다.
- 한 줄 안내: 만 14세 이상만 이용할 수 있어요.

## 화면 계약 (프런트 작업자)

- love.html 마법사에 새 단계(이메일). 이메일 입력 칸(기존 결제 창의 도메인 버튼 @naver.com 등 재사용 가능), [필수] 동의 체크, [선택] 광고성 정보 체크, '무료 분석 보기 전에 이메일만 확인할게요' 같은 안내. 단계 수 표시 갱신.
- /api/love/preview 요청 본문에 추가: `leadFlow: 2`, `leadEmail`(string), `agreeLeadPrivacy`(true 필수), `agreeMarketing`(boolean).
- 응답의 `lead`가 { saved, emailQueued } 로 온다. 실패해도 결과 화면은 그대로 보여 준다(메일은 부가).
- 결제 창 이메일 칸(#deliveryEmail)을 같은 이메일로 미리 채운다(수정 가능).
- SoTrack.emailSubmit('love_timing') → Meta trackCustom 'EmailSubmit', GA 'email_submit'(세션당 1회, 이메일 값은 절대 싣지 않음).
- 메일 링크로 들어오는 `love.html?lead=<토큰>` 이면 서버에서 저장된 입력을 받아 바로 무료 결과를 다시 그린다(입력 단계 건너뜀, 이메일 단계도 건너뜀).

## 서버 계약 (서버 작업자)

- 새 테이블 love_leads: id, token(무작위 32자 이상, 다시 보기·수신 거부 겸용), email, name, birth_json(입력값), situation, start_ym, top1_ym(1위 달 'YYYY-MM', 메일 외 노출 금지), agree_privacy_at, agree_marketing_at(null 가능), unsubscribed_at, result_mail_sent_at, followup1_sent_at, followup3_sent_at, top1_alert_sent_at, purchased_at, created_at, delete_after.
- POST /api/love/preview: leadFlow===2이면 이메일 형식·agreeLeadPrivacy===true 필수(400 + 한국어 오류). 같은 이메일+같은 입력은 새 행 대신 갱신. leadFlow 없으면 기존 동작(구버전 화면 호환).
- GET /api/love/lead/:token → 저장 입력으로 만든 preview 응답(만료·삭제·없는 토큰은 404).
- GET /unsubscribe?t=<토큰> (또는 /api/love/unsubscribe) → 즉시 수신 거부 기록 + 확인 화면. 수신 거부 시 마케팅 보관 연장이 끝나 delete_after = 지금+30일 이내로.
- 결과 메일(거래 정보, '(광고)' 없음): 제목 "{이름}님의 무료 연애 사주 분석", 본문: 1위 달 구간 첫 문장, 3위 달과 쉬운 말 풀이, '메일에서 결과 다시 보기' 링크(love.html?lead=토큰). 구매 권유 문구는 링크 한 줄로 최소화.
- 판매 메일(동의자만, 제목 앞 '(광고)', 본문 끝: 보낸 곳 사주보는 수달·연락처·수신 거부 링크): D+1 "{이름}님, 가장 강한 달은 {구간}에 있어요", D+3 "1·2위 달과 그달에 해볼 일", 1위 달 1일 "지금이 {이름}님의 인연 신호가 가장 강한 달이에요". 링크는 love.html?lead=토큰&utm_source=email&utm_campaign=love_followup&utm_content=d1|d3|top1.
- 발송 시간: 판매 메일은 10:00~20:00 KST 사이에만(야간 광고 전송 금지). 기존 jobs 방식(setInterval)으로 10분마다 대상 확인. 구매자(같은 이메일로 love_timing 결제 완료)는 판매 메일 중단.
- delete_after 지난 행은 privacyMaintenance 작업에서 삭제.
- 메일 발송은 src/email/resend.js 재사용. 테스트 모드·키 없음이면 실제 발송하지 않고 기록만.

## 방침(서버 작업자)

public/privacy.html: 수집 항목·목적·보관 기간 표에 '무료 연애 분석 이메일' 행, 광고성 정보 수신 항목, 수신 거부 방법을 추가. 상단 개정 안내 "2026년 11월 16일 개정·시행: 무료 분석 이메일 수집과 광고성 정보 수신(선택) 추가".

## 테스트

필수 동의 없음·잘못된 이메일 거부, 구버전 요청 호환, 토큰 다시 보기, 수신 거부, 야간 발송 금지, 구매자 판매 메일 중단, 30일 삭제, 메일 본문에 1위 달 정확한 연·월이 결과 메일에는 없음(1위 달 알림 메일에서만 '이번 달'로 표현), EmailSubmit에 이메일 값 미포함, 모바일 통합 흐름(이메일 단계 → 결과 → 결제 창 이메일 미리 채움).
