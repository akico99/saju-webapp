# 연애 시기 리포트 설계

작성 2026-10-22. 사용자 승인: 구조 개편 방향과 가격표("현대 승인 전까지 미리 만들어놓는 방향으로 진행"). 근거 문서: 사주-웹툰/분석/2026-10-22-서비스-구조-개편안.md.

## 목표

연애 고민이 있는 사람이 생년월일과 지금 상황을 입력하면, 로그인 없이 내 사주표·오행·타고난 매력·앞으로 12개월 연애 흐름(계절 단위)을 무료로 보고, 19,900원을 내면 인연 신호가 가장 강한 세 달과 상대 유형·만남의 자리·조심할 신호·상황별 할 일을 모바일 화면으로 받는다.

## 범위

이번 하위 과제(A)만 만든다. 운영에는 환경변수 LOVE_TIMING_ENABLED=true일 때만 열린다. 기본값은 꺼짐이다.

다음 하위 과제는 각자 설계·계획을 따로 둔다.

- B 가격표·메뉴 개편: 궁합 24,900원, 평생사주 39,000원, 신년운세 14,900원, 3,900원 상품 메뉴 정리와 구매자 추가 상품
- C 비회원 결제(휴대폰·이메일), 결과 링크 발송. 미공개 점검 브랜치(codex/service-audit-remediation) 반영 뒤
- D 재회 리포트 24,900원
- E 단계별 측정 이벤트, 후기 수집, 공유 카드
- F 연애 시기 리포트 PDF

## 흐름

1. /love.html: 수달이 한 화면에 한 질문씩 묻는다. 지금 상황(솔로, 썸, 연애 중, 이별 후) → 이름·성별 → 생년월일·양력/음력 → 태어난 시각(모름 가능)
2. POST /api/love/preview (로그인 없음, LLM 없음) → 무료 첫 장
3. "전체 풀이 열기 19,900원" → POST /api/love (로그인 필요). 로그인 안 했으면 401 → 기존 PayFlow.toLogin이 입력값을 저장하고 로그인 후 같은 페이지로 돌아온다. 돌아오면 입력값을 복원하고 무료 첫 장을 다시 보여 준다
4. 포인트가 없으면 402 → 기존 카드 결제(PayFlow.checkout('love', form)) → 승인 후 서버가 같은 폼으로 생성 시작 → /love.html?jobId=... 에서 진행 상황을 본다
5. 완료되면 /api/status/:jobId 의 report(본문)·visual(12개월 막대)로 결과를 그린다. 마이페이지 주문 목록에서 다시 볼 수 있다

## 무료 첫 장 (POST /api/love/preview)

입력: situation(single|some|dating|breakup), name, gender(남|여, 필수), year, month, day, calendar, isLeap, hour, minute, hourUnknown.

응답 reading:

- situation: { key, label }
- pillars: 기존 freeReadings의 기둥 목록(시각 모르면 시주 제외)
- balance: 기존 오행 밸런스의 bars·headline
- charm: 기존 타고난 매력의 headline·base·found
- seasons: 이번 달부터 12개월을 3개월씩 묶은 4칸. 칸마다 { label("2026년 10~12월"), level(강함|보통|잔잔함), avg }
- strongCount: 12개월 중 점수 65 이상인 달 수
- locked: 유료에서 열리는 장 제목 목록(상황에 맞춘 마지막 장 제목 포함)
- price: 19900

무료 응답에는 달별 점수와 달 이름을 담지 않는다. 가장 강한 달은 결제 후에만 서버가 계산해 내려보낸다.

## 유료 본문

엔진 확정값: 앞으로 12개월 연애 점수(monthlyFlow topic love, 성별 반영), 그중 상위 세 달(점수 높은 순, 같으면 이른 달), 현재 대운 흐름, 일간, 일지(배우자 자리)의 십신·12운성·신살, 일지와 맺은 합·충, 배우자 별(여성 관성, 남성 재성)과 표현의 별(식상) 개수, 도화살 여부, 용신, 신강약.

LLM 한 번 호출, 소제목 순서 고정:

1. 한 줄 답: 가장 강한 달과 그때 할 일 하나를 2~3문장으로
2. 인연 신호가 강한 세 달: 달마다 "**YYYY년 M월**"로 시작하는 문단
3. 나에게 끌리는 사람
4. 내가 끌리는 사람
5. 만남이 생기기 쉬운 자리
6. 반복되기 쉬운 연애 패턴
7. 조심할 인연의 신호
8. 상황별 장: 솔로 "솔로인 지금 할 일", 썸 "썸을 연애로 바꾸려면", 연애 중 "지금 관계를 깊게 하려면", 이별 후 "이별 뒤 지금 할 일"
9. 월별 한 줄: 12줄 "- N월: ..."

말투와 금지:

- 사주보는 수달이 고객에게 말하듯 다정하고 분명한 존댓말("~해요"). 각 장의 첫 문장이 답이다
- 확정값의 달을 바꾸지 않고 "12개월 중 인연 신호가 가장 강한 달"처럼 비교로 분명히 말한다. 점수 숫자는 인용하지 않는다(공통 원칙 2)
- "반드시", "100%", "확실히 생긴다" 금지. 상대의 키·외모·직업명·특정 날짜처럼 엔진에 없는 사실 금지. 상대 속마음 단정 금지
- 이별 후 상황에서 재회를 권하거나 말리지 않는다
- 공통 원칙(baseSystemPrompt.BASE_RULES)을 모두 따른다

저장: result_text는 "## 제목" 섹션 묶음, result_visual은 12개월 막대(상위 세 달 강조) HTML. PDF는 만들지 않는다(F).

## 상품 등록

- productKey love_timing, 가격 19,900원(points.PRICES), 결제 상품 종류 'love', 결과 페이지 /love.html
- 게이트 꺼짐: /love.html, /love-app.js, /love.css, /api/love* 는 404, SELLABLE과 추적 카탈로그에서 빠지고 resolveProduct('love')는 null
- 주문 이름 "연애 시기 리포트 — {이름}"

## 오류

- 입력 오류·성별 없음·상황 없음: 400과 한국어 안내
- 같은 상품 생성 중: 409 already_pending(기존 심층 리딩과 같음)
- 생성 실패: 주문 오류 처리와 기존 refundPurchase 환불(카드 결제는 기존 흐름이 취소)

## 검증

- 단위: 무료 응답에 달별 정보가 없음, 계절 4칸·라벨, 상위 세 달 순서, 프롬프트에 확정값·상황 반영, 본문 파싱이 소제목 누락에도 무너지지 않음
- HTTP: 게이트 꺼짐 404·켜짐 200, preview 200/400, /api/love 비로그인 401, 로그인·잔액 0이면 402
- 화면: 390px에서 입력 4단계, 무료 첫 장, 잠금, 결과 화면 육안 확인
- 실제 생성 1회(수동 스크립트)로 말투·분량·금지 규칙 확인
