# SEO·검색 노출 운영 계획

작성일: 2026-10-07 (Asia/Seoul) · 대상: https://sajuotter.com · 운영 책임: 대표 / 기술·콘텐츠 실행: 에이전트

## 1. 목표와 원칙

한국어 사주 질문을 검색한 사람이 유용한 설명을 발견하고, 무료 체험과 필요한 유료 PDF 리포트로 이동하게 만든다. 구글·네이버를 우선하고, 빙과 AI 검색, 이미지·소셜 유입을 같은 콘텐츠에서 확장한다. 플랫폼 수보다 실제 발견·색인·검색 유입·전환을 측정한다.

- 검색엔진 지침을 지키는 정공법만 사용한다. 링크 구매, 가짜 후기, 검색 순위 조작, 내용이 같은 대량 랜딩, 반복 키워드 삽입은 하지 않는다.
- `HTTP 200 → 수집 가능 → 실제 수집 → 색인 → 노출 → 클릭 → 구매`는 서로 다른 단계다. 각 단계의 증거 없이 다음 단계까지 완료라고 쓰지 않는다. IndexNow 접수도 색인 완료가 아니다.
- 측정 날짜·대상 URL·배포일·출처·수치를 함께 남긴다. 계정 접근이나 숫자가 없으면 **미확인**으로 기록한다. 실제 0건을 측정한 경우만 `0`을 쓴다.
- 로컬 구현 완료와 운영 반영 완료를 분리한다. 메타·sitemap·robots는 `scripts/buildSeo.js`를 원장으로 수정하고 생성한다. 운영 점검은 배포 환경의 공개 상품·가격 설정을 기준으로 한다.
- 생년월일·개인 결과·주문/PDF 주소를 검색 도구나 공개 로그에 보내지 않는다. robots는 접근 제어가 아니므로 개인 리포트는 서버 인증으로 보호한다.
- 광고·소셜 게시 뒤 생긴 방문을 자연검색 개선으로 계산하지 않는다. 자연검색은 검색 도구 보고서로, 광고·소셜은 채널별 UTM과 집계로 구분한다. 광고 시작 예정일 2026-10-08은 전달받은 일정이며 실제 집행은 미확인이다.

### 현재 기준선과 보정

2026-10-04 감사 문서와 2026-10-07 일부 운영 URL의 Googlebot UA 요청을 확인했다. 이는 실제 검색엔진 서버의 수집 성공을 입증하지 않는다.

### 자동 스크립트의 점검 범위와 한계

`scripts/seoMonitor.js` 결과를 원장으로 삼되 지원 여부는 구현된 스크립트의 도움말·코드와 대조한다. 다음은 요구 범위이며 구현되지 않은 항목은 에이전트 보완 점검으로 명시한다.

2026-10-07 구현 확인 시점: 상태·주요 메타·canonical·일반 robots meta/X-Robots-Tag noindex·h1·JSON-LD 파싱·PAGES 대조·robots/llms 응답·OG 이미지 응답·없는 주소 404·http/www의 301 상태·IndexNow 키·연도 참고 경고를 지원한다. **가격/통화와 화면/설정 일치, 개별 봇 meta·중복 메타, robots 그룹별 해석과 전체 차단, 301 목적지/루프, 내부 링크, 연도 의미 판정은 추가 에이전트 점검 대상**이다. 스크립트가 보강되면 이 목록도 갱신한다. 경고의 제목/설명 길이·본문 800자 기준은 내부 휴리스틱이며 공식 순위 요건이 아니다.

- `PAGES`의 공개 sitemap 대상과 운영 sitemap을 정규화해 대조하고, 비활성 신년 상품·개인·결제 URL의 잘못된 포함을 찾는다. 단순 전체 URL 개수로 비교하지 않는다.
- 각 공개 응답의 상태코드, 중복/빈 title·description, canonical의 호스트·목표·중복, `robots`/개별 봇 meta와 `X-Robots-Tag` noindex를 확인한다.
- HTML의 h1 존재·내용과 JSON-LD 파싱·Offer 통화/가격을 점검한다. 설정/표시 가격의 비교 원장을 분명히 한다. 로컬 환경의 상품 공개 설정이 운영과 다르면 별도 경보로 기록한다.
- robots의 공개 URL 허용과 개인 경로 차단, sitemap 선언, llms의 존재·판매 중인 상품·가격·링크를 확인한다. noindex 읽기가 필요한 폐기 페이지를 먼저 robots로 막지 않는다.
- 없는 URL의 실제 404, http·www에서 대표 https 주소로 이동하는 경로, 리다이렉트 루프·잘못된 목적지를 확인한다. 구형 JS 이동 stub은 HTTP 301과 구분한다.
- 연도 낡음은 페이지 의미로 판단한다. 2026 무료 도감의 2027 '내년' 설명은 정상이고 2027 전용 상품은 2026년에도 2027 표기가 정상이다.
- OG 이미지 200·Content-Type·URL, 내부 링크, IndexNow 키 파일 접근은 지원되지 않으면 주간 에이전트가 보완한다. h1이 `sr-only`인지만으로 색인 실패라고 판정하지 않는다.
- 이 점검은 JS 실행 후 개인 결과, 진짜 Googlebot IP 접근, Search Console 색인, 검색 순위, 웹 성능 현장 데이터까지 증명하지 않는다.

2026-10-04 문서의 '14일 재측정'은 **실제 배포일부터 계산한 최소 중간 확인 간격**이다. 첫 효과 판단은 완료된 28일 이상, 지속 판단은 8~12주로 잡는다. 계정 데이터가 늦게 집계되면 최근 미완료 일자를 제외한다. 10월 7일 배포를 가정하면 10월 9일 기술/발견, 10월 14일 수집, 10월 21일 중간 확인, 11월 4일 4주 검토다. 실제 배포일이 다르면 일정도 이동한다.

### 플랫폼별 공식 근거

- IndexNow 공식 참가 레지스트리에는 Bing, Yandex, Seznam, Naver, Yep, Internet Archive, Amazonbot이 있다. Google은 목록에 없다. 보관 서비스와 웹 검색 서비스를 동일한 노출 채널로 세지 않는다. Internet Archive의 현재 통지 수신 설정은 도구 접근 실패로 미확인이다. 한 참여 endpoint 통지로 공유되지만 각 엔진의 색인/순위는 별개다. [참가 레지스트리](https://www.indexnow.org/searchengines.json), [공식 FAQ](https://www.indexnow.org/faq), [접수·키 규격](https://www.indexnow.org/documentation)
- 빙 등록은 직접 소유확인 또는 Search Console 가져오기가 가능하다. 가져오기는 Google 계정 접근 권한이 필요하므로 사용자 선택이다. [Bing 등록 안내](https://www2.bing.com/webmasters/help/add-and-verify-site-12184f8b)
- 네이버는 RSS보다 sitemap 활용을 권장한다. RSS는 발행 글·동일 도메인·본문 전체 등이 필요하므로 글이 없는 현 단계에서는 우선하지 않는다. [RSS·sitemap 제출](https://searchadvisor.naver.com/guide/request-feed), [URL 검사](https://searchadvisor.naver.com/guide/url-inspection)
- AI 브리핑은 요약과 출처를 제공하지만 항상 표시되지는 않는다. 외부 사이트 전용 신청이나 선정 보장 방식은 확인하지 못했다. 원문 품질 개선은 권장 전략이며 선정 보장 사실이 아니다. [네이버 AI 브리핑 소개](https://help.naver.com/service/5626/contents/24119)
- 다음은 대표 홈 사이트 등록과 등록조회가 있으며 지역정보는 카카오맵으로 분리된다. 신청은 노출 보장이 아니고, 영리 사이트의 업종별 자료·기재 사항은 실제 신청 화면에서 확인한다. [등록조회](https://register.search.daum.net/searchForm.daum?act=search), [등록 기준](https://register.search.daum.net/info.daum?act=guidet1)
- 카카오는 URL 메타정보 조회와 캐시 초기화를 제공한다. 문서의 대상은 공유/메시지 API의 스크랩 메시지 및 카카오스토리이며 모든 일반 채팅·기존 메시지의 일괄 갱신 보장은 확인하지 못했다. [URL 메타정보 도구 안내](https://developers.kakao.com/docs/ko/tool/common), [캐시 문제 FAQ](https://developers.kakao.com/docs/ko/message-template/faq)
- 다른 메신저마다 캐시와 도구가 다르다. [Meta Sharing Debugger](https://developers.facebook.com/tools/debug/)는 이번 조회에서 429로 최신 사용법 미확인이고, [LinkedIn Post Inspector](https://www.linkedin.com/post-inspector/)도 로그인 이후 동작 미확인이다. 모든 플랫폼의 공통 캐시 갱신 시간을 가정하지 않는다.
- 구글 이미지는 img src와 이미지 주변 본문을 사용하고 CSS 배경 이미지와 구분한다. Discover는 색인·정책 조건이 기본이며 신청이나 노출 보장이 없다. [이미지 가이드](https://developers.google.com/search/docs/appearance/google-images), [Discover 가이드](https://developers.google.com/search/docs/appearance/google-discover)
- Google Business Profile은 온라인 전용을 제외한다. 네이버 플레이스는 위치·전화번호가 이용자에게 의미가 있어야 하며 일부 온라인 쇼핑몰도 그 조건을 요구한다. 이 서비스 제외는 현재 온라인 전용 서비스 형태에 대한 판단이다. [Google 등록 자격](https://support.google.com/business/answer/13763036), [네이버 플레이스 기준](https://new.smartplace.naver.com/help/policy?menu=regist)

### AI 크롤러 robots 정책 권장안

**현재 권장: 공개 설명·웹툰·판매 중인 서비스는 검색/사용자 요청 봇 접근을 유지한다.** 현 `User-agent: * / Allow: /`와 기존 개인·결제 경로 Disallow가 이를 허용한다. 노출을 위해 불필요한 봇별 그룹을 추가하지 않는다. 봇별 그룹을 만들면 일반 그룹의 개인 경로 차단을 자동 상속한다고 가정하지 말고 동일 정책을 재적용한다. [Bing robots 주의사항](https://www.bing.com/webmasters/help/how-to-create-a-robots-txt-file-cb7c31ec)

| 엔진 | 검색/사용자 요청 | 학습 정책 | 권장과 근거 |
|---|---|---|---|
| OpenAI | `OAI-SearchBot`, `ChatGPT-User` | `GPTBot`은 학습 목적 제어 | SearchBot 허용 유지. GPTBot 허용을 검색 노출 요건으로 취급하지 않음. ChatGPT-User는 사용자 요청이라 robots 규칙이 적용되지 않을 수 있음 |
| Perplexity | `PerplexityBot`, `Perplexity-User` | 공식 설명상 두 봇은 기초 모델 학습 수집용이 아님 | 공개 콘텐츠 접근 허용. User는 일반적으로 robots를 무시할 수 있으므로 서버 인증으로 개인 결과 보호 |
| Anthropic | `Claude-SearchBot`, `Claude-User` | `ClaudeBot`은 학습 목적 | 검색/요청 봇 허용. 학습 봇 차단 여부를 검색 봇과 분리 가능 |
| Google | `Googlebot`, `Googlebot-Image` | `Google-Extended`가 Gemini 학습 및 일부 grounding도 제어 | Googlebot 허용. Gemini 발견 확대 목적이면 현재 Extended 허용 유지를 권장하되 학습도 허용됨을 기록. Extended 차단은 Google Search 포함·순위에 영향 없음 |

현재 학습 봇을 별도로 차단하지 않는 정책도 * 그룹으로 허용되고 있다. 검색 노출 확대 작업만을 이유로 학습 정책을 바꾸지 않는다. 별도의 콘텐츠 사용 정책이 정해지면 GPTBot·ClaudeBot과 Google-Extended의 차이를 반영한다. 공개 UA 요청 200만으로 진짜 봇 접근을 인증하지 않으며, WAF 예외가 필요하면 공식 IP/검증 절차도 사용한다.

근거: [OpenAI 봇](https://developers.openai.com/api/docs/bots), [Perplexity 봇](https://docs.perplexity.ai/docs/resources/perplexity-crawlers), [Anthropic 봇](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler), [Google 크롤러](https://developers.google.com/crawling/docs/crawlers-fetchers/google-common-crawlers)

`llms.txt`는 서비스·가격·대표 URL을 정리한 보조 문서로 유지한다. 접근 허용이나 색인 지침을 대신하지 않으며 모든 AI가 사용한다는 증거도 없다. 구글은 llms.txt가 검색 노출·순위에 영향을 주지 않는다고 명시한다. 구글 AI 검색에는 별도 특수 마크업이 필요 없으며 색인과 일반 SEO가 기본이다. [Google 공식 업데이트(2026-06-15)](https://developers.google.com/search/updates), [AI 검색 가이드](https://developers.google.com/search/docs/appearance/ai-features)

## 4. 개선 백로그와 실행 순서

**먼저 자동 기술 감시·계정 기준선, 그다음 기존 무료 페이지의 설명 보강, 이후 첫 질문형 랜딩을 만든다.** 기존 페이지는 이미 서비스로 연결되어 있어 작은 수정으로 이용자 이해를 개선하고, 신규 랜딩은 실제 질문 수요를 확인한 뒤 넓힌다. 구조화 데이터 개수 증가를 먼저 목표로 삼지 않는다.

| 순서 | 작업·이유 | 담당 | 한 작업을 끝내는 조건 |
|---|---|---|---|
| P0-1 | seoMonitor 정착과 3대 검색 도구 기준선. 성과를 평가할 자료가 현재 없음 | 에이전트/사용자 | 운영 기술 보고서 저장·실패 경보 작동 상태 확인, GSC·네이버·빙에서 날짜/기간/노출/클릭/색인 사유 기록. 자료 없으면 기술 완료·성과 미확인으로 분리 |

## 6. 자동화 설계와 프롬프트

보고서는 로그 전용 폴더에 날짜별로 보관하고 최신본도 유지한다. 같은 오류의 식별자는 URL+검사명으로 관리하고 최초/최근 발생·완화/해결·다음 확인일을 남긴다. 새 경보·악화·실패·사용자 조치가 있어야 알림을 보낸다. 기술 결과가 같고 행동할 일이 없으면 조용히 둔다. 사용자 계정 자료 요청도 월간 기한 도래 또는 새로운 문제 때 한 번 묶어 전달한다.

2026-10-07 생성된 스크립트의 CLI를 읽어 확인했다. `--base-url`은 대상 사이트, `--out`은 **보고서 디렉터리**(기본 `docs/seo-reports`), `--json`은 stdout JSON 출력이다. 기본 실행은 `<날짜>.md`와 `latest.json`을 저장하며 `--no-write`는 저장을 생략하고 `--timeout`은 요청 제한시간(ms)을 지정한다. 종료코드 `0`은 치명 오류 없음(경고는 있을 수 있음), `1`은 치명 오류, `2`는 옵션/실행 실패 또는 사이트맵 네트워크 실패다. 일부 요청 실패가 치명 항목으로 기록되는 경우도 있으므로 종료코드와 JSON을 함께 읽는다. 날짜별 원본 JSON이 필요하면 latest.json을 날짜/시각 이름으로 복사 보관한다. 자동화는 루트 에이전트가 만든다.

### 주간 점검 프롬프트 초안

```text
node scripts/seoMonitor.js --base-url https://sajuotter.com --out docs/seo-reports --json

서비스 저장소에서 위 명령을 실행한다. docs/seo-monitoring-plan.md의 주간 기준을 따른다. 실행 결과 JSON·종료코드와 이전 보고서, 마지막 운영 배포일을 비교하고 날짜별 보고서와 최신본을 보관한다. 같은 날짜에 다시 실행하면 날짜.md가 덮어써지므로 필요한 원본은 시각별로 보관한다. 옵션 미지원·파일 부재·네트워크 실패를 성공으로 처리하지 않는다. 종료코드 0이어도 경고와 미지원 점검을 확인한다.

공개 상태코드·메타·canonical·noindex(meta/X-Robots-Tag)·h1·JSON-LD·PAGES↔sitemap·robots·llms·404/대표 도메인 이동·OG 이미지·IndexNow 키·연도 문구를 확인한다. 문서의 미지원 목록에 따라 가격/통화·화면/설정 일치, 개별 봇 meta·중복, robots 그룹/전체 차단, 리다이렉트 목적지/루프, 내부 링크와 연도의 의미를 보완 확인한다. 비활성 신년 상품 예외와 운영/로컬 공개 설정 차이를 구분한다. 11월 다음 연도 문구 경고만으로 무료 도감을 2027로 올리지 않는다.

새 오류는 재확인 후 URL·관측 시각·현재/이전 값·영향·다음 조치를 기록한다. 안전한 기술 수정은 이미 승인된 범위에서 진행하고 운영 반영과 로컬 완료를 구분한다. 검색 계정 접근이 없으면 실제 색인/노출/클릭을 미확인으로 유지한다. 사용자 제출 자료가 있으면 완료된 7일 비교와 URL 검사 사유만 검토한다. 자료나 계정 등록이 필요한 경우 사용자 조치를 한 번에 묶는다.

변화가 없거나 조치할 일이 없으면 조용히 둔다. 신규 경보·악화·실행 실패·해결 등 의미 있는 변화 또는 사용자 조치 필요 시에만 알린다. 같은 미확인 상태나 기존 경고를 매번 재알림하지 않는다. 기술 정상만으로 SEO 성과 달성을 주장하지 않는다.
```

### 월간 점검 프롬프트 초안

```text
node scripts/seoMonitor.js --base-url https://sajuotter.com --out docs/seo-reports --json

서비스 저장소에서 위 명령을 실행한다. JSON·종료코드와 docs/seo-monitoring-plan.md의 월간·재측정 기준, 미지원 보완 점검 목록, seo-platform-checklist.md를 따른다. 최신 기술 보고서와 이전 월간 보고서, 실제 배포일, 사용자 제공 검색 도구 자료를 비교한다. 종료코드 0을 전체 항목 정상으로 해석하지 않는다.

완료된 28일 대 이전 28일의 구글·네이버·빙 노출/클릭/CTR·색인 사유를 URL·브랜드/비브랜드·모바일별로 정리한다. 실제 자료가 없으면 미확인으로 남긴다. 소표본·계절성·10월 광고·소셜 유입을 구분하고 30% 감소는 문서의 최소 표본 조건과 함께 적용한다. 배포 14일은 중간 확인이며 콘텐츠/타이틀 효과는 4주 이상 본다. 신규 4주 미색인 URL은 수집일·선택 canonical·중복·본문·robots를 조사한다.

질문형 랜딩·기존 무료 본문·웹툰의 완료 조건과 유입을 평가해 다음 개선 한 가지를 선택한다. 고정 질문 표본으로 AI 엔진/네이버 AI 브리핑의 출처 URL·날짜·조건을 기록하고 전체 인용률로 일반화하지 않는다. 주요 플랫폼의 공식 등록/크롤러/구조화 데이터 정책 변경만 확인해 출처를 남긴다. 10~12월에는 무료 도감의 실제 연도와 별도 2027 상품 공개를 구분한다.

변화가 없거나 조치할 일이 없으면 조용히 둔다. 신규 경보·실패·정책 변화·측정상 의미 있는 악화·사용자 조치 필요 시에만 알린다. 계정 요청은 새로 필요한 자료와 기한을 한 번에 묶고 반복 상태 알림을 남기지 않는다. 결과를 로컬 보고서로 보관하고 숫자 없이 노출 개선 완료라고 주장하지 않는다.
```

### 권장 일간 경량 운영

같은 기술 명령을 매일 실행하고 결과와 직전 보고서만 비교한다. 주간 콘텐츠 검토와 월간 성과 분석을 매일 반복하지 않는다. 일간 예약의 완료 조건은 예약 저장·실행 가능 환경·첫 보고서·실패 알림 확인이다. 이 문서 작성 자체는 예약 생성이나 24시간 가동의 증거가 아니다.

## 7. 기록 형식

월간 표의 필수 열: `측정일 / 엔진 / 완료 기간 / URL·검색어 그룹 / 노출 / 클릭 / CTR / 색인 상태·사유 / 마지막 수집일 / 배포일 / 출처 보고서 / 다음 확인일`.

AI 출처 표본: `날짜 / 엔진·모드 / 로그인·언어·지역 조건 / 질문 / 답변 출처 URL / 서비스·가격 정확성 / 이전 결과와 차이`. 검색량·전체 인용률·실제 전환이 없으면 미확인이다. 새 페이지마다 구조적 완료, 운영 완료, 검색 반영, 유입 평가를 각각 기록한다.
