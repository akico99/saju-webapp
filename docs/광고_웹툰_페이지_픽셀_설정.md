# 광고 웹툰 페이지와 픽셀 설정 가이드

작성일: 2026-10-03 · 코드 반영: 2026-10-07  
기준: 현재 저장소의 정적 웹툰 페이지와 공용 추적 코드

## 요약

새 웹툰 페이지를 만들 때 Meta·카카오 픽셀 코드를 페이지마다 복사하지 않는다. `public/webtoon/lifetime.html`을 템플릿으로 사용하고, GA4 코드와 `/track.js`를 한 번씩 포함한다. `/track.js`가 서버 설정에서 픽셀 ID를 받아 Meta·카카오 스크립트를 불러온다.

현재 `TRACKING_START`는 **2026-10-08 00:00 KST**다. 그 시각 전에는 `/api/tracking-config`가 Meta·카카오 픽셀 ID를 `null`로 보내므로 두 픽셀 스크립트는 불러오지 않는다. GA4는 페이지의 별도 태그로 계속 동작한다.

### 시작일 전 유입정보 처리 — 2026-10-07 수정 반영

- 서버가 기존 `TRACKING_START` 상수로 시행일을 판단하고 `/api/tracking-config`의 `attributionEnabled`로 내려준다. 설정 응답은 캐시하지 않는다.
- 브라우저는 서버 응답이 `true`일 때만 UTM·`fbclid`·`gclid`·외부 유입 도메인을 저장한다. 브라우저 시계는 시작일 판단에 사용하지 않는다.
- 시작일 전 응답을 받으면 과거 구현이 남긴 `so_attr_first`·`so_attr_last`를 삭제한다. 설정 대기·요청 실패·시작일 전에는 결제 준비에 유입값을 전달하지 않는다.
- 서버도 시작일 전에는 주문에 유입정보를 저장하지 않는다. 픽셀 ID가 없어도 시작일 이후 유입 저장과 GA4 구매 퍼널은 동작한다.
- 시작 시각 직전·정각, 브라우저 시계 차이, 설정 실패, 기존 유입값 제거, 픽셀 ID 없음과 구매 중복 방지를 회귀 검사했다. Render 등록과 실제 플랫폼 수신은 계정 확인이 필요하다.

## 새 웹툰 페이지 만들기

1. `public/webtoon/lifetime.html`을 복사해 `public/webtoon/<주제>.html`로 만든다.
2. 제목, 설명, OG 메타, 웹툰 이미지와 대사, CTA 문구 및 도착 경로를 새 광고 소재에 맞게 바꾼다.
3. 기존 페이지처럼 GA4 태그와 `/track.js`를 포함한다. 같은 태그를 중복 삽입하지 않는다.
4. 픽셀 ID를 HTML·JavaScript 소스에 직접 적지 않는다. Render 환경변수로 전달한다.

예시 태그 위치:

```html
<!-- 기존 GA4 설정 코드 -->
<script async src="https://www.googletagmanager.com/gtag/js?id=G-THWHBPH5WR"></script>
<script>
  window.dataLayer = window.dataLayer || [];
  function gtag(){dataLayer.push(arguments);}
  gtag('js', new Date());
  gtag('config', 'G-THWHBPH5WR');
</script>

<!-- Meta·카카오 픽셀은 이 파일에서 직접 초기화하지 않는다. -->
<script src="/track.js"></script>
```

## Render 환경변수

Render 서비스의 환경변수에 다음 이름으로 픽셀 ID를 설정하고, 서비스를 재시작 또는 배포한다.

| 변수 | 값 |
| --- | --- |
| `META_PIXEL_ID` | Meta Events Manager에서 발급한 Pixel ID |
| `KAKAO_PIXEL_ID` | 카카오 비즈니스 픽셀 & SDK의 Track ID |

실제 ID는 코드나 문서, 광고 URL에 기록하지 않는다. 실제 Render 등록 상태는 별도로 대시보드에서 확인해야 한다. 카카오 픽셀은 사이트 설치 외에 해당 픽셀을 사용할 광고계정과의 연동도 필요하다. [카카오 픽셀 & SDK 설정 안내](https://kakaobusiness.gitbook.io/main/tool/pixel-sdk/install)

## 광고 URL과 UTM

소재마다 `utm_content` 값을 고유하게 지정한다. 그래야 웹툰 페이지 방문부터 결제까지 어떤 소재가 유입을 만들었는지 구분할 수 있다.

```text
https://sajuotter.com/webtoon/lifetime.html?utm_source=meta&utm_medium=paid_social&utm_campaign=lifetime_webtoon_2026q4&utm_content=panel_01
```

카카오 광고에는 `utm_source=kakao`를 쓴다. 예를 들어 `utm_content=panel_02`처럼 패널·후킹 문구별로 이름을 정한다. 공용 추적 코드는 UTM과 `fbclid`, `gclid`를 첫 유입 및 마지막 유입 정보로 브라우저에 저장하고, 결제 준비 요청 때 서버로 전달한다. 브라우저 저장과 서버 주문 저장은 모두 시작일 전 차단한다. 서버 설정 대기·실패 때에도 브라우저 유입값을 전달하지 않는지 공개 전 테스트에서 확인한다.

## 이벤트 흐름

| 사용자 행동 | 현재 수집 이벤트 | 메모 |
| --- | --- | --- |
| 웹툰 랜딩 방문 | GA4 `page_view`, Meta `PageView`, 카카오 `pageView` | Meta·카카오는 픽셀 ID가 공개되는 날짜 이후에 동작 |
| 유료 상품 상세 보기 | GA4 `view_item`, Meta `ViewContent`, 카카오 `viewContent` | `/lifetime-report.html` 등 등록된 상품 경로에서 자동 발생 |
| 결제 시작 | GA4 `begin_checkout`, Meta `InitiateCheckout`, 카카오 `viewCart` | 결제 주문이 준비된 뒤 결제 페이지에서 발생 |
| 결제 승인 | GA4 `purchase`, Meta `Purchase`, 카카오 `purchase` | 승인된 결제에서 주문번호 기준 중복을 막음 |

웹툰 페이지 자체는 현재 상품 상세 페이지로 취급하지 않아 기본 방문 이벤트만 보낸다. CTA 클릭만 별도로 세고 싶으면 공용 추적 코드에 GA4 `select_content`와 이에 대응하는 픽셀 이벤트를 추가한다. Google은 콘텐츠 선택, 상품 조회, 결제 시작, 구매 이벤트를 권장 이벤트로 안내한다. [GA4 권장 이벤트](https://support.google.com/analytics/answer/9267735?hl=en)

테스트 결제는 Meta·카카오에 실제 `Purchase`로 보내지 않는다. GA4에는 `purchase_test`로만 기록한다. 실제 구매 측정 결과를 확인할 때 이 차이를 고려한다.

## 공개 전 점검표

- 웹툰 URL이 모바일 화면에서 정상 표시되고 CTA가 의도한 상품 페이지로 이동한다.
- 광고 URL의 UTM 값이 올바른지 확인한다. 시작일 전에는 브라우저 `localStorage`에 유입값이 새로 저장되지 않고 기존 유입값이 제거되는지, 시작일 이후에는 브라우저와 주문에 유입값이 저장되는지 확인한다.
- 현재 설정일(2026-10-08 00:00 KST) 이후 `/api/tracking-config`가 설정된 픽셀 ID를 반환하는지 확인한다. 시작일 전에는 `null`이 정상이다.
- Meta Events Manager의 테스트 이벤트와 Meta Pixel Helper에서 랜딩 `PageView`, 상품 페이지 `ViewContent`, 결제 흐름 이벤트를 점검한다.
- 카카오 비즈니스에서 픽셀의 웹사이트·광고계정 연동 및 방문·구매 이벤트 수신을 확인한다.
- GA4 DebugView 또는 실시간 보고서에서 이벤트 이름과 결제 금액·상품 항목을 확인한다.
- 테스트 결제의 Meta·카카오 구매 이벤트가 발생하지 않고, 실제 승인된 결제만 `Purchase`로 수집되는지 구분한다.

## 관련 코드

- 기존 광고 웹툰: `public/webtoon/lifetime.html`
- 공용 브라우저 추적 및 UTM 저장: `public/track.js`
- 픽셀 ID·상품 목록 제공: `src/server/routes/tracking.js`
- 픽셀 공개 시작일: `src/config/tracking.js`
- 주문 유입정보 시작일 검사: `src/db/cardPayments.js`
- 결제 시작 이벤트: `public/pay.html`
- 승인된 구매 이벤트: `public/pay-success.html`
